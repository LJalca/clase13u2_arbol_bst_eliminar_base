¿Por qué Eliminar en un BST es más Delicado que Insertar?

➕

Insertar (Sesión 12)

Siempre bajamos hasta encontrar un espacio vacío (null) al final de una rama y colocamos el nodo nuevo como una hoja. Nunca movemos nodos existentes.

✂️

Eliminar (Hoy • Sesión 13)

El nodo a borrar puede estar en medio del árbol sosteniendo uno o dos subárboles enteros. Si lo quitamos sin cuidado, desconectamos a sus hijos o rompemos la regla izquierdo < raíz < derecho.

Los 3 Casos de Eliminación en un BST

CASO 1 • 0 Hijos

Nodo Hoja

No tiene descendientes (izq == null && der == null). Simplemente desconectamos el enlace del padre devolviendo null.

Dificultad: Directa
CASO 2 • 1 Hijo

Nodo con un Solo Hijo

Tiene únicamente subárbol izquierdo o derecho. El padre hace un puente directo adoptando al único hijo disponible.

Dificultad: Puente simple
CASO 3 • 2 Hijos

Nodo con Dos Hijos

Reemplazamos su valor por su Sucesor Inorden (el menor valor del subárbol derecho) y luego eliminamos ese sucesor repetido.

Dificultad: Reemplazo + borrado

Caso 1 (AD) • Nodo sin Hijos

Eliminar un Nodo Hoja (Ejemplo: Borrar 20)

¿Qué ocurre?

El nodo 20 no tiene hijos. Al retornar null a su padre (30), el enlace 30.izquierdo queda vacío y el resto del árbol ni siquiera se toca.

if (actual.izquierdo == null && actual.derecho == null) {
    return null;
}
Inorden antes: 20 → 30 → 40 → 50 → 70 | Después: 30 → 40 → 50 → 70Detalle Caso 2 ➔
Caso 2 (AD) • Puente Directo

Eliminar un Nodo con 1 Hijo (Ejemplo: Borrar 30)

¿Por qué sigue siendo BST?

Como todo el subárbol de 30 ya era menor que 50, al subir 40 directamente al enlace izquierdo de 50, la propiedad de orden se conserva intacta.

if (actual.izquierdo == null) return actual.derecho;
if (actual.derecho == null) return actual.izquierdo;
El hijo único ocupa exactamente el lugar que dejó el nodo eliminadoDetalle Caso 3 (Dos Hijos) ➔
Caso 3 (AD) • El Corazón de la Eliminación

Eliminar un Nodo con 2 Hijos usando el Sucesor Inorden

¿Quién es el Sucesor Inorden?

Es el valor inmediatamente mayor al nodo que vamos a eliminar. En el BST siempre se encuentra con una regla infalible:

1 paso a la DERECHA ➔ bajar todo a la IZQUIERDA

Por ser el mínimo del subárbol derecho, cumple dos propiedades vitales: es mayor que todo el subárbol izquierdo y menor que el resto del subárbol derecho.

Receta en 3 Pasos (Ejemplo: Borrar 50)

  1. Localizar el sucesor: Entrar al subárbol derecho de 50 (70) y bajar al extremo izquierdo → hallamos 60.
  2. Copiar el dato: Reemplazar 50 por 60 (¡no destruimos los enlaces de la raíz!).
  3. Borrar el duplicado: Eliminar el 60 original dentro del subárbol derecho (garantizado que será Caso 1 o Caso 2, porque el mínimo nunca tiene hijo izquierdo).
Alternativa equivalente: Predecesor Inorden (mayor valor del subárbol izquierdo)Simulador Interactivo 1 ➔

Cuando borras un cliente o producto en PostgreSQL/MySQL, el motor elimina la clave de su árbol índice y reequilibra nodos para que las futuras consultas SELECT sigan siendo instantáneas.

Análisis de Rendimiento (AD) • Degradación

¿Cuándo y Por qué se Degrada un BST?

Causas Principales de Degradación

  • Datos ya ordenados: Insertar 10, 20, 30, 40, 50 (o al revés) crea una sola rama inclinada de altura n.
  • Eliminaciones asimétricas repetidas: Usar siempre el Sucesor Inorden (subárbol derecho) en miles de borrados acorta el lado derecho y deja más profundo el lado izquierdo.

Impacto Real en Consultas

Balanceado (1,000 nodos) → Altura ≈ 10 → máx. 10 pasos
Degenerado (1,000 nodos) → Altura = 1,000 → hasta 1,000 pasos

Conclusión: la velocidad de un BST depende directamente de su altura (O(h)).

Un BST sin control de altura puede perder toda su ventaja algorítmicaIntroducción al Balanceo ➔
Introducción al Balanceo (AD) • Concepto AVL

Factor de Equilibrio y Rotaciones Simples

Regla del Factor de Equilibrio (FE)

FE(nodo) = altura(izquierdo) - altura(derecho)
  • Si FE ∈ {-1, 0, +1} en todos los nodos → el árbol está Balanceado.
  • Si |FE| ≥ 2 en algún nodo → existe Desequilibrio (riesgo de degradación).

¿Cómo Corrigen el Desequilibrio los Árboles AVL?

Mediante rotaciones (izquierda o derecha): reorganizan localmente 3 nodos para reducir la altura en 1 nivel sin perder jamás la propiedad de orden BST.

Ejemplo: si tenemos 10 → 20 → 30 (altura 3, FE = -2), una Rotación a la Izquierda sube a 20 como raíz con hijos 10 y 30 (altura 2, FE = 0).
Árboles AVL y Red-Black automatizan este equilibrio en cada inserción y borradoSimulador Interactivo 3 ➔

Hallando el Sucesor Inorden: encontrarMinimo()

ArbolBST.java — encontrarMinimo(NodoBST nodo)
public int encontrarMinimo(NodoBST nodo) {
    NodoBST actual = nodo;
    while (actual.izquierdo != null) {
        actual = actual.izquierdo;
    }
    return actual.dato;
}

¿Cómo se usa al eliminar?

Cuando queremos el Sucesor Inorden de actual (Caso 3), llamamos a encontrarMinimo(actual.derecho).

¿Por qué un ciclo while simple?

Porque en un BST el valor más pequeño de cualquier subárbol siempre está bajando únicamente por izquierdo hasta topar con null.

Paso previo indispensable para resolver el Caso 3Código: Casos 1 y 2 ➔
Explicación de Código 2 (AP) • Búsqueda + Casos 1 y 2

Método eliminar(int valor) — Primera Parte

public void eliminar(int valor) {
    raiz = eliminarRecursivo(raiz, valor);
}

private NodoBST eliminarRecursivo(NodoBST actual, int valor) {
    if (actual == null) return null;

    if (valor < actual.dato) {
        actual.izquierdo = eliminarRecursivo(actual.izquierdo, valor);
    } else if (valor > actual.dato) {
        actual.derecho = eliminarRecursivo(actual.derecho, valor);
    } else {
        // Caso 1: Hoja
        if (actual.izquierdo == null && actual.derecho == null) return null;
        // Caso 2: Un solo hijo
        if (actual.izquierdo == null) return actual.derecho;
        if (actual.derecho == null) return actual.izquierdo;
        // Caso 3 continúa en la siguiente diapositiva...
    }
    return actual;
}
1. Reconexión Automática:

Escribir actual.izquierdo = eliminarRecursivo(...) actualiza el enlace del padre con lo que devuelva el hijo (null en Caso 1 o el nieto en Caso 2).

2. Si el valor no existe:

El caso base if (actual == null) return null; detiene el recorrido sin lanzar error ni modificar el árbol.

Explicación de Código 3 (AP) • Caso 3 (Dos Hijos)

Tres Líneas que Resuelven el Caso de Dos Hijos

Dentro del bloque else (actual tiene ambos hijos):
// Paso 1: Encontrar el sucesor inorden (mínimo del lado derecho)
int sucesor = encontrarMinimo(actual.derecho);

// Paso 2: Copiar el valor del sucesor en el nodo actual
actual.dato = sucesor;

// Paso 3: Eliminar el valor repetido en el subárbol derecho
actual.derecho = eliminarRecursivo(actual.derecho, sucesor);
¿Por qué no entra en bucle infinito?

Porque sucesor es el nodo más a la izquierda del subárbol derecho, así que jamás tiene hijo izquierdo. Al borrarlo en el Paso 3, siempre cae en Caso 1 o Caso 2 y termina de inmediato.

Ventaja de Copiar el Dato:

No necesitamos re-enlazar manualmente el subárbol izquierdo del nodo borrado; ese enlace permanece intacto.

public int calcularFactorEquilibrio(NodoBST nodo) {
    if (nodo == null) return 0;
    return calcularAlturaRecursivo(nodo.izquierdo)
         - calcularAlturaRecursivo(nodo.derecho);
}

private boolean estaBalanceadoRecursivo(NodoBST nodo) {
    if (nodo == null) return true;
    int factor = calcularFactorEquilibrio(nodo);
    return Math.abs(factor) <= 1
        && estaBalanceadoRecursivo(nodo.izquierdo)
        && estaBalanceadoRecursivo(nodo.derecho);
}
